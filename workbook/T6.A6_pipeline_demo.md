# Workbook 2, section 4.5: live pipeline demo (about 5 minutes)

A script for showing the data pipeline live: ingestion, transformation, warehouse, monitoring and management. Run it on the machine that holds the credentialed data. Every command prints counts, check names and run IDs only, never record text, so the screen can be shared.

## Before the demo

```bash
cd ~/dev/Final_project/Clinical-Discharge-Treatment-Plan-Verification
source .venv/bin/activate
export MIMIC_DIR=$HOME/data/mimic
```

Have `results/workbook2/figures/4_5_warehouse_lineage.png` and `4_5_monitoring.png` open in another window.

## 1. The architecture (30 s)

Show `4_5_warehouse_lineage.png`. Source files → data-quality gate → `raw` → `staging` → `mart`, with every run logged in `ops`. DuckDB is one local file (`$MIMIC_DIR/warehouse/clinverify.duckdb`), so the data never leaves the authorised machine.

## 2. Ingest, transform, load (1 min)

```bash
python scripts/run_pipeline.py --trigger demo
echo "exit code: $?"
```

What to point out: `status: ok`, 2,400 cases, 14 checks, 0 failed, about 5 seconds, exit code 0.

## 3. What the warehouse holds (1 min)

```bash
python - <<'EOF'
import sys; sys.path.insert(0, "src")
from clinverify import warehouse as W
con = W.connect(W.DEFAULT_DB)
print(W.layer_counts(con).to_string(index=False))
print(con.execute("SELECT split, COUNT(*) AS cases, COUNT(DISTINCT subject_id) AS patients FROM mart.cases GROUP BY split ORDER BY split").df().to_string(index=False))
EOF
```

What to point out: raw → staging row counts reconcile (for example, `discharge_procedures` 2,122 → 2,116 after 5 duplicates and 1 empty row), and the mart splits are 1,840 / 460 / 100 with no patient in two splits.

## 4. Monitoring: a bad load is caught (1 min)

```bash
python scripts/run_pipeline.py --inject-fault --trigger demo-fault
echo "exit code: $?"
```

What to point out: the corrupted copy (duplicated cases, emptied notes, a dropped key column, an unknown case ID, missing radiology) fails the gate with 5 problems in under a second. The status is `failed_checks` and the exit code is 1. **Nothing was written**: run step 3 again and the counts have not changed.

## 5. Run history and alerting (1 min)

```bash
python scripts/run_pipeline.py --history
```

Show `4_5_monitoring.png`. Every run, good or bad, is in `ops.pipeline_runs` with its duration and check counts. A scheduler alerts on any non-zero exit code: 0 ok, 1 check failed, 2 error.

## 6. Scheduling (30 s)

Nightly at 02:00 with cron (`crontab -e`):

```
0 2 * * * cd ~/dev/Final_project/Clinical-Discharge-Treatment-Plan-Verification && MIMIC_DIR=$HOME/data/mimic .venv/bin/python scripts/run_pipeline.py --trigger cron >> $HOME/data/mimic/warehouse/cron.log 2>&1
```

WSL does not keep cron running on its own, so on Windows use Task Scheduler with the action `wsl.exe` and arguments
`-e bash -lc "cd ~/dev/Final_project/Clinical-Discharge-Treatment-Plan-Verification && .venv/bin/python scripts/run_pipeline.py --trigger task-scheduler"`.

## If something goes wrong

- `FileNotFoundError`: `MIMIC_DIR` is not set, or the data is not at `$MIMIC_DIR/mimic-iv-ext-cdm-1.1/` and `$MIMIC_DIR/physionet.org/files/mimiciv/3.1/hosp/admissions.csv.gz`.
- `IO Error: Could not set lock`: the notebook still holds the database open. Restart the notebook kernel.
